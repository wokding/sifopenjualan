## 📜 Code of Conduct

This project and everyone participating in it is governed by our commitment to fostering an open and welcoming environment. We expect all contributors to:

- Use welcoming and inclusive language
- Be respectful of differing viewpoints and experiences
- Gracefully accept constructive criticism
- Focus on what is best for the community
- Show empathy towards other community members

## 🚀 How Can I Contribute?

### 🐛 Reporting Bugs

Before creating bug reports, please check existing issues to avoid duplicates. When creating a bug report, include:

- **Clear title and description**
- **Steps to reproduce** the behavior
- **Expected behavior** vs actual behavior
- **Screenshots** if applicable
- **Environment details** (PHP version, MySQL version, Browser, OS)

### 💡 Suggesting Enhancements

Enhancement suggestions are tracked as GitHub issues. When creating an enhancement suggestion, include:

- **Clear title** describing the enhancement
- **Detailed description** of the proposed functionality
- **Why this would be useful** to most users
- **Possible implementation** (if you have ideas)

### 📝 Code Contributions

1. Fork the repository
2. Clone your fork locally
3. Create a branch for your feature
4. Make your changes
5. Test thoroughly
6. Submit a pull request

## 🛠️ Development Guidelines

### PHP Guidelines

- Follow **PSR-2** coding standard where possible
- Use **meaningful variable names**
- Add **PHPDoc comments** for functions
- Keep functions **small and focused**
- Use **CodeIgniter best practices**

### JavaScript Guidelines

- Use **modern ES6+ syntax**
- Add **comments** for complex logic
- Use **SweetAlert2** for user notifications
- Test in multiple browsers

### Database Guidelines

- Use **prepared statements** (CodeIgniter Query Builder)
- Add **proper indexes**
- Use **transactions** for multi-table operations
- Document schema changes

### UI/UX Guidelines

- Maintain **consistent design** with SB Admin 2 template
- Ensure **responsive design**
- Use **Bootstrap 4** components
- Add **loading states**
- Provide **clear user feedback**

## 🔄 Pull Request Process

1. ✅ Test your changes thoroughly
2. ✅ Update documentation if needed
3. ✅ Check for console errors
4. ✅ Ensure no merge conflicts
5. ✅ Follow coding standards
6. ✅ Create Pull Request with clear description
7. ✅ Wait for review and address feedback

## 📐 Style Guide

### Git Commit Messages

Use **present tense** and **imperative mood**:

```
✅ Good:
- Add customer import from Excel
- Fix toast notification persistence bug
- Update README with installation steps

❌ Bad:
- added stuff
- bug fix
- changes
```

### Commit Types

- `feat:` New feature
- `fix:` Bug fix
- `docs:` Documentation only
- `style:` Code style (formatting)
- `refactor:` Code refactoring
- `perf:` Performance improvement

## 🧪 Testing

Test before submitting:

1. **Functionality** - Feature works as expected
2. **Edge Cases** - Unusual inputs
3. **Browser Compatibility** - Chrome, Firefox, Edge
4. **Mobile Responsiveness** - Mobile devices
5. **Performance** - No significant slowdown
